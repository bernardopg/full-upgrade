## Comportamentos erráticos e lacunas do script

1. **Verde com vulnerabilidades persistentes.** `audit_cargo_bins()` retorna 0 quando todos cargo-installed têm memo recente e rustup já está no latest (`lib/steps/lang_rust.sh:157` em diante). `autofix_rust_cves()` também retorna 0 quando remediação não conseguiu remover problemas e não houve falha de rebuild (final do arquivo). Isso comunica execução técnica concluída, mas o resumo visual não conserva a distinção de segurança. Melhor resultado: registrar `known-unresolved`/aviso persistente separadamente do exit operacional, sem repetir compilação nem declarar sistema corrigido.

2. **Memo não prova que novas falhas são conhecidas.** Arquivo `/home/bitter/.cache/system-upgrade/rust-cve-rebuild-nofix.tsv` contém `cargo-outdated\t0.19.0\t1790272358`: 24/09/2026 17:52:38 UTC. TTL 7d expira em 01/10/2026 17:52:38 UTC. Chave é somente crate+versão+tempo, sem IDs dos advisories nem hash do binário; nova vulnerabilidade na mesma versão pode herdar classificação informativa e pular tentativa. TTL evita rebuild caro e é razoável para a mesma falha; preservar lista de IDs/hash impediria declarar nova falha como já tentada. Não significa que chegou fix compatível para gix-date: a faixa semver confirma bloqueio real.

3. **Auditoria duplicada mesmo sem mudança.** A etapa 41 audita sete arquivos e a 42 repete a auditoria imediatamente, trazendo o mesmo DB e índice, antes de descobrir no-op. Compartilhar resultado estruturado por hash de binário entre etapas elimina repetição preservando nova auditoria quando binários mudarem. Neste run foram 11s+8s, além da poluição duplicada no log.

4. **`CVEs antes: 2` mede executáveis.** `parse_cargo_vuln_bins()` (`lib/core.sh:733`) extrai basenames de `vulnerabilities found in` e faz `sort -u`; número resultante é binários, não vulnerabilidades. Texto deve ser `binários vulneráveis antes/depois`; para contar advisories usar IDs únicos e associação a binário. Isso também evita chamar todos advisories de CVE.

5. **Avisos relevantes não entram em remediação.** O parser não reconhece `allowed warnings found`: faster-hex tem solução compatível, mas cargo-audit não entra na fila de rebuild. Unsound com `patched` deve ser considerado elegível; unmaintained sem fix deve permanecer diagnóstico, sem rebuild cego.

6. **Erros de auditoria não ligados a rede podem desaparecer.** `_rust_collect_vuln_bins()` conserva stderr no log, mas só retorna RC_WARN se regex detectar rede. Outro erro com rc!=0 e sem linha parseável de vulnerabilidade vira lista vazia e sucesso. `audit_cargo_bins()` tem fallback de `^error:`, mas o coletor usado na remediação não. O código de saída deve distinguir falha operacional de resultado com vulnerability; nunca transformar auditoria inconclusiva em `Sem CVEs corrigíveis`.

7. **Atualizações com falha são toleradas e depois classificadas como upstream.** Auto-remediação usa `_rust_run_capture rustup ... || true` e `cargo install-update ... || true`; isso conserva fluxo, mas perde a causa operacional. Fora deste run, download/build falho pode terminar com nota que afirma latest sem prova. Guardar rc dos comandos e só classificar `upstream sem fix` após consulta válida e audit concluído.

8. **`rustup check` com erro não padrão pode ser aceito como latest.** O gate verifica `_rc != RC_WARN`, não sucesso estrito 0; ausência da string Update available com saída vazia/erro não classificado pode justificar informativo. Resultado desconhecido deve ser inconclusivo. Neste run rustup check foi bem-sucedido e afirmou latest (588–590); problema é preventivo derivado do fluxo, não incidente confirmado.

9. **Cobertura limitada a `$CARGO_HOME/bin`, arquivos regulares.** `find -type f` ignora symlinks. Aqui symlinks cargo/rustc apontam para proxy rustup, então auditá-los de novo seria duplicação; porém os executáveis reais de cargo/rustc no diretório da toolchain não foram auditados. Também ficaram de fora Rust bins de pacman, `/usr/bin`, `~/.local/bin` etc. `Sem CVEs críticas em binários cargo do usuário` não deve ser lido como auditoria de toda máquina. O script não aplica corte de severity crítica: inclui advisory médio e baixo.

## Recomendações em ordem

1. Corrigir apresentação: separar sucesso de execução de achados não resolvidos, distinguir binários/advisories/CVEs e cobertura completa/parcial.
2. Incluir tokensave via teto ajustável do cargo-audit; corrigir tratamento de falhas inconclusivas nos dois caminhos.
3. Rebuild auditable direcionado de cargo-audit com deps frescas para faster-hex e dos bins reconstruíveis para melhorar cobertura. Nenhum rebuild global é necessário para comprovar o bloqueio semver de gix-date/git2.
4. Para cargo-outdated, manter achados visíveis; preferir aguardar versão que atualize cadeia Cargo/gix ou remover se não necessário. Fork/patch local só se a ferramenta for indispensável, seguido de teste funcional e audit. Para rustup, release upstream com h2/rustls corrigidos; rebuild próprio é alternativa técnica, com custo de manutenção e necessidade de preservar instalação/proxies.
5. Memorizar IDs do conjunto não corrigido e reutilizar auditoria apenas se binários/DB/política forem os mesmos.
